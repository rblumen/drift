# Drift — Codebase Audit (2026-07-01)

Full-scope audit of the Drift portfolio rebalancer at commit `54c6ab3` (main).

**Scope:** general code review; comment and test coverage; duplication / simplification
opportunities; validity of implemented logic against PRINCIPLES.md (systematic per-goal
conformance); GitHub issue context; dependency & supply-chain check; privacy-guarantee
verification; UI accessibility; docs accuracy.

**Method:** every engine and ingest source file was read in full; UI shell, store, and
key panels were reviewed; `npm test` (418 tests, all passing), `npm run test:coverage`,
`npx tsc -b`, and `npm audit` were run; one suspected engine bug was confirmed with a
throwaway failing test (not committed).

---

## Executive summary

The codebase is in strong shape where it matters most: the engine is pure, deterministic,
heavily commented (comment quality is genuinely exceptional — nearly every non-obvious
decision is annotated with its rationale and issue number), and covered by 418 passing
tests including a scenario harness that maps fixtures to PRINCIPLES.md goals. All eleven
governing goals are implemented and verified (see conformance matrix below).

Three findings are rated **major**:

1. **Demo mode can destroy the user's real saved portfolio** — autosave is not gated on
   demo mode, so loading the demo and touching anything overwrites `localStorage` with
   demo data (and the rolling backups age out within ~15 minutes).
2. **The project has never been type-checked** — `tsc` in the build script is a no-op
   against the solution-style `tsconfig.json`, CI runs tests only, and a real `tsc -b`
   reports **58 errors** across 10 files, 9 of them in production code.
3. **`REVISIT_PLACEMENT` silently fails to fire on a fully in-tolerance portfolio**,
   violating a documented domain invariant (confirmed by test).

The rest is a set of minor issues (docs drift, a privacy-promise gap from Google Fonts,
dead-domain share links, duplicated default tables) and worthwhile enhancements
(schema-derivation to collapse hand-synced class lists, extracting a duplicated
balance-correction pass, CI hardening, accessibility work).

## Major issues

### M1 — Demo mode overwrites the user's real saved data

`src/App.tsx`: the autosave effect (line ~83) persists to the primary `localStorage`
slot on every state change, unconditionally. `isDemoMode` (line 65) gates only the
banner. Consequences:

- A returning user with real data who clicks **Try the demo** on the landing page (or
  visits `?demo`) and then changes *anything* — a tab-triggering state edit, a strategy
  tweak to explore — has their real portfolio overwritten by demo state via `saveState`.
- The 3-slot rolling backup (5-minute interval) also starts snapshotting demo state, so
  the real data rotates out of all recovery paths within ~15 minutes of demo use.
- This directly contradicts the demo banner ("Your saved data is untouched.") and
  CONTEXT.md ("Demo mode: … without touching localStorage").

**Fix:** gate both `saveState` and `saveBackup` on `!isDemoMode` (and decide what
exiting demo mode via the banner ✕ should restore). A regression test in
`store.test.ts`/an App-level test is warranted given the data-loss severity.

### M2 — Type-checking is a no-op; 58 real type errors exist

- `package.json` build script is `tsc && vite build`, but `tsconfig.json` is a
  solution-style config (`"files": []`, references only). Plain `tsc` (without `-b`)
  compiles **nothing** and exits 0. Vite's own build does not type-check either.
- CI (`.github/workflows/ci.yml`) runs `npm test` only — no type-check, no build.
- `npx tsc -b --force` reports **58 errors in 10 files**, including production code:
  - `src/App.tsx` (3): the Zod-inferred `AppState['strategy']` is structurally
    incompatible with the engine `Strategy` type (`placement` is
    `Record<string, string[]>` vs `Record<AssetClass, PlacementTarget[]>`). The
    engine/ingest seam is currently type-unsound and only works by accident of runtime
    shape.
  - `src/ingest/adapters/empower.ts` (1): `EMPOWER_TICKER` is declared
    `Record<AssetClass, string>` but defines only 6 of 19 classes — see m4.
  - `vite.config.ts` (1): invalid plugin overload.
  - Dead code (TS6133) in `rollup.ts`, `ClassifyPanel.tsx`, `DonutChart.tsx`,
    `ResultsPanel.tsx`.
  - 45 errors in `rebalance.test.ts` + others: test fixtures with partial
    `targets`/`tickerOverrides` maps that no longer satisfy the widened `AssetClass`
    union.

**Fix:** change the build script to `tsc -b && vite build`, fix the 58 errors (most test
errors are mechanical — a `makeTargets(partial)` helper or `satisfies Partial<…>`), and
add the type-check (or full `npm run build`) to CI so it can't regress. Add
`*.tsbuildinfo` to `.gitignore` before doing so (see m10).

### M3 — `REVISIT_PLACEMENT` is not emitted when the portfolio is within tolerance

`src/engine/rebalance.ts`: when every class is within its tolerance band, the function
returns early (line ~808) *before* Step 9 (line ~1301) where `REVISIT_PLACEMENT` is
computed. Confirmed empirically: a portfolio exactly on target held 100% in a taxable
account (taxable share 1.0 > FI target 0.2) produces zero trades and **no**
`REVISIT_PLACEMENT` flag.

This violates the documented invariant, which is explicitly drift-independent:

- CLAUDE.md: "Emit `REVISIT_PLACEMENT` when taxable share of total > the fixed-income
  target weight." (unconditional)
- README: "a standing heads-up … independent of how you configure placement."

The flag is precisely most useful when nothing else is wrong — it is the only signal
telling a balanced household that its *placement* strategy has expired. The
`householdValue === 0` early return (harmless) and the all-within-tolerance return both
skip it.

**Fix:** hoist the Step 9 check above the early returns (it depends only on
`accountValues`/`householdValue`, which are available). Per repo test hygiene, add a
regression scenario `issue-N-revisit-placement-within-tolerance.scenario.json`.

## Minor issues

### m1 — Google Fonts breaks the "no network calls" privacy promise

`index.html` loads Schibsted Grotesk and IBM Plex Mono from `fonts.googleapis.com` /
`fonts.gstatic.com`. Every page load sends the user's IP and user agent to Google. The
landing page trust strip says "Runs entirely in your browser … No telemetry"; README
says "No network calls… no data leaves your machine." No portfolio data leaks, but the
literal promise is false, and this is the kind of gap a privacy-conscious reviewer will
find. **Fix:** self-host the two font families (e.g. via `@fontsource/*` packages) and
drop the preconnects. Consider a CSP header (see e8) to make "no network calls"
enforceable rather than aspirational.

### m2 — Share links point at a domain the project may not own

`src/ui/ResultsPanel.tsx:376` shares `SHARE_URL = 'https://drift.app'` (X/Twitter,
Reddit, Facebook, email, SMS, copy-link), while `src/ui/ics.ts:13` uses
`DRIFT_URL = 'https://drift-rebalance.vercel.app/'`. `drift.app` is not this project's
deployment — every share/copy action distributes a wrong (potentially squattable) URL.
Also two constants exist for what should be one canonical URL. **Fix:** single exported
constant, set to the real production URL.

### m3 — `PROJECTED_OFF_TARGET` check uses an inconsistent reachable target

`src/engine/rebalance.ts` Step 11 (line ~1384) compares projected weights against
`strategy.targets[ac] * scale`, but Step 5 sizes each class at
`(targetValue[ac] − immovableByClass[ac]) * scale` *plus* the immovable value already on
the books. For a class with locked/immovable value `i` and `scale ≠ 1`, the expected
resting point differs from `target × scale` by `i × (1 − scale)` — enough to spuriously
raise or mask the flag in portfolios that combine locked positions with frozen
(within-tolerance) classes. Plausible edge case rather than confirmed defect; worth a
targeted test. **Fix:** compute the reachable target as
`(immovable + (target − immovable) × scale) / householdValue`.

### m4 — `EMPOWER_TICKER` covers 6 of 19 asset classes

`src/ingest/adapters/empower.ts:99`. The map predates the hierarchy expansion. If
`parseEmpowerTotals` is ever called with a total for a newer class (e.g. `REAL_ESTATE`,
`MUNI_BOND`), it emits a position with `ticker: undefined`, which will fail schema
validation downstream at best. Today the Empower-totals UI only offers the six legacy
classes, so this is latent — but it is exactly the kind of bug the (currently broken)
type-check exists to catch. **Fix:** either complete the map or narrow the type to the
supported subset and derive the UI options from it.

### m5 — The asset-location default table is maintained twice

`DEFAULT_STRATEGY.placement` (`src/engine/strategy.ts:46`) and `DEFAULT_PLACEMENT`
(`src/ingest/schema.ts:94`) are two hand-maintained copies of the same 19-row table.
They agree today; nothing keeps them agreeing. **Fix:** export one table from the engine
and import it in the schema migration (ingest → engine is the allowed dependency
direction).

### m6 — CHANGELOG has two `[0.1.0]` releases and duplicated subsection headers

`CHANGELOG.md` contains `## [0.1.0] - 2026-07-01` *and* `## [0.1.0] - 2026-05-29`. The
July release (PR #109) shipped a large feature set (placement specificity #89,
hierarchy #36, tax adjustment #7, drawdown #14, wash-sale #5, three new importers…) —
under semver that is at minimum **0.2.0**, and Keep a Changelog requires unique version
headings (the link references at the bottom can only point one place). The 2026-07-01
block also repeats `### Added`/`### Changed` headers (lines 12/27/42/60/83), which Keep
a Changelog 1.1.0 disallows. `package.json` still says `0.1.0`. **Fix:** rename the
July block (0.2.0), merge the duplicate subsections, fix the link refs, and consider a
release-skill check for "version already released".

### m7 — Documentation drift (CONTEXT.md, README, IMPLEMENTATION_PLAN.md)

- **CONTEXT.md** (last updated 2026-05-29): "164 passing tests" (now 418); "P0 next
  targets" lists #2/#3/#5/#6 — all closed; the architecture tree omits `detect.ts`, the
  Vanguard/E*TRADE/Merrill adapters, `hierarchy.ts`, `placementHierarchy.ts`,
  `taxAdjust.ts`, `metrics.ts`, `cashfill.ts`, `nativeAllocation.ts`, `taxableSale.ts`,
  the scenario harness, `LandingPage`, `AllocationPlot`, `ReminderPanel`, `ics.ts`.
- **README**: the Flags reference lists 6 of the 14 `Flag` kinds (missing
  `EXCESS_CASH`, `PROJECTED_OFF_TARGET`, `TAXABLE_REBALANCE_AVOIDABLE`,
  `WITHDRAWAL_SHORTFALL`, `BLENDED_FUND_OVERSELL`, `BLENDED_FUND_SOLD`,
  `MISSING_COST_BASIS`, `WASH_SALE_RISK`, `FIVE_TWENTY_NINE_REBALANCE_LIMIT`); the
  "Default placement rules" table describes the pre-#89 defaults (equities now prefer
  TAX_FREE → TAX_DEFERRED, bond sub-classes differ); the project-structure tree is
  similarly stale.
- **IMPLEMENTATION_PLAN.md**: the "Domain model (as built)" `AssetClass` union predates
  the hierarchy (no REAL_ESTATE, bond/intl/alt sub-classes) and the `Flag` union is
  missing the five newest kinds.

Individually cosmetic; collectively they erode the "docs are authoritative" premise the
repo leans on. A doc-sync pass tied to the next release would clear all of it.

### m8 — 9 npm audit vulnerabilities in the dev-dependency chain

`npm audit`: 9 vulnerabilities (3 critical, 2 high, 3 moderate, 1 low), all in build/test
tooling — `esbuild ≤0.24.2` (via vite 5) and `undici 7.x` (via the vitest/vite chain).
No *runtime* dependency (react, react-dom, papaparse, zod) is affected, and the shipped
app is static, so user exposure is nil; the realistic risk is dev-machine/CI. Fixes ride
the major upgrades (vite 8, vitest 4) — see e7.

### m9 — Accessibility is thin across the UI

Only ~44 ARIA/label/keyboard hits across 21 components. Notable gaps (spot-checked, not
exhaustive): the SVG charts (`PieChart`, `DonutChart`, `StackedBars`, `AllocationPlot`)
have no `role="img"`/`<title>`/text alternative, so Results is largely invisible to a
screen reader; banner dismiss buttons are bare "✕" with no `aria-label`; the tab nav is
plain buttons without `role="tablist"`/`aria-selected`/arrow-key support; several inputs
rely on visual adjacency rather than `htmlFor`/`aria-label`. Given the tool now has a
public landing page and share CTAs, a focused a11y pass (axe-core in CI, chart alt
summaries, labeled controls) is worth scheduling; overlaps with open issue #28 (mobile).

### m10 — `.gitignore` oddities

- `*.html` ignores every HTML file repo-wide; `index.html` is only tracked because it
  was added before the pattern. Anyone adding a new tracked HTML asset will hit a
  confusing silent ignore. Prefer anchored ignores (`/rebalance-report-*.html`,
  `/html/`) plus `!/index.html`.
- `*.tsbuildinfo` is not ignored — the moment the type-check is fixed (M2), stray
  `tsconfig.*.tsbuildinfo` artifacts will appear as untracked files.

### m11 — Suspect wiring: `taxAdjustedTargetWeights` receives nominal projected weights

`src/App.tsx:396` passes `result.taxAdjusted ? result.projectedWeights : undefined` into
`StrategyPanel`'s `taxAdjustedTargetWeights`, which feeds the "nominal vs after-tax
composition" compare bars (`StrategyPanel.tsx:354`). `result.projectedWeights` is the
*nominal* projected view; the after-tax view is `result.taxAdjusted.projectedWeights`.
As written, the "after-tax" bar renders nominal data whenever they differ. Looks like a
one-line wiring slip (`result.taxAdjusted?.projectedWeights`); verify intent against
issue #7's design before changing.

## Enhancements

### e1 — Extract the duplicated per-account balance-correction pass

`rebalance.ts` Step 8.5 (lines ~1048–1075) and the tax-adjusted nominal re-balance
(lines ~1221–1244) are the same algorithm copy-pasted (shrink largest opposite-sign
trade, drop below `minTradeUsd`, repeat). Extract
`correctAccountNets(trades, accounts, expectedNetOf, minTradeUsd)`.

### e2 — Derive the Zod schemas and per-class tables from `ALL_ASSET_CLASSES`

Adding one asset class currently touches at least six hand-synced structures:
`types.ts` (union + `ALL_ASSET_CLASSES`), `schema.ts` (`ASSET_CLASSES`, every
`targetsSchema` field, the sum-refine expression, `DEFAULT_PLACEMENT`),
`strategy.ts` (targets + placement), plus UI label maps. `targetsSchema` in particular
can be generated (`z.object(Object.fromEntries(ALL_ASSET_CLASSES.map(...)))` with a
generic sum refine), and `ASSET_CLASSES` can be `ALL_ASSET_CLASSES as [AssetClass, ...]`.
This is the highest-leverage simplification in the repo — it converts a class-addition
from a shotgun edit into a two-file change and eliminates the whole category of error
behind m4.

### e3 — Decompose `rebalance.ts` (1,451 lines)

The orchestrator has absorbed drawdown, deposits, tax adjustment, blended funds, and
cash surfacing. Helpers exist, but the main function is still ~900 lines with three
near-duplicate early-return result builders. Natural seams: a `buildResult()` assembler,
and moving the wash-sale/529/REVISIT flag passes into a `deriveAdvisoryFlags()` module
(which would also have prevented M3, since the early returns could share it).

### e4 — `parseMoney` doesn't handle parenthesized negatives

`src/ingest/csv.ts:41` handles `$-50.00` but not the `(1,234.56)` accounting style some
broker exports use for negative/pending amounts. Cheap to add alongside a fixture.

### e5 — UI-layer test coverage

Engine coverage is excellent (98% stmts / 100% funcs, thresholds enforced); ingest and
store are well tested. The UI has a single test file (`ics.test.ts`). The two most
test-worthy non-React modules are untested: `exportReport.ts` (627 lines — the artifact
users act on at their broker; a prior regression, #56, lived exactly in this layer) and
`fmt.ts` (all display rounding). Both are pure-ish and cheap to test without DOM
tooling; panel component tests can come later.

### e6 — Harden CI

Add `tsc -b` (after M2) and `npm run build` to `ci.yml` so type errors and build breaks
block PRs; consider `npm audit --omit=dev --audit-level=high` as a soft gate.

### e7 — Dependency currency

Everything is one or two majors behind: React 19, Vite 8, Vitest 4, Zod 4, Tailwind 4,
TypeScript 6. None is urgent (see m8 for the security angle). Sequencing suggestion:
Vite + Vitest first (clears all audit findings), Zod second (touches `schema.ts` only),
React/Tailwind last (broad UI surface).

### e8 — Ship security headers via `vercel.json`

A `Content-Security-Policy` (e.g. `default-src 'self'` once fonts are self-hosted per
m1, plus `connect-src 'none'`-style tightening), `X-Content-Type-Options`, and
`Referrer-Policy` would turn the privacy guarantee into something the browser enforces
and users can verify.

### e9 — `diversification()` normalizes over always-zero classes

`src/engine/metrics.ts:29` normalizes the inverse-HHI by `N = 19`, including
`US_TOTAL_MARKET` (always 0 by invariant) and mutually-exclusive parent/child classes —
so the theoretical max is unreachable and the reading compresses as more sub-classes are
added to the type. Normalizing over "live" classes (parent-or-children, not both) would
make the axis stable. Cosmetic; the plot is directional anyway.

### e10 — Resolve the #99 (PostHog analytics) conflict explicitly

Open issue #99 proposes PostHog event tracking for feedback selections. That directly
contradicts the hard guardrail ("no telemetry in v1") in CLAUDE.md, README, CONTEXT.md,
IMPLEMENTATION_PLAN.md, and the landing-page trust strip. Whichever way it goes, the
decision should be recorded and the guardrail text updated *first* — otherwise the trust
strip becomes false advertising the moment the issue merges. (Opt-in telemetry with the
strip amended is a coherent middle path.)

## Test & coverage assessment

- **418 tests / 16 files**, all passing. Engine coverage 98.1% statements, 100%
  functions, 88.8% branches, with 80% thresholds enforced (scoped to `src/engine/**`).
- The scenario harness (#33/#34) is a standout: JSON fixtures schema-validated, named
  per PRINCIPLES goal, zero-code discovery; the regression-fixture policy (one
  `*.scenario.json` per engine bug) is being followed (`regressions/` holds #5, #42,
  #83, #84/#87 fixtures).
- Gaps: UI layer (see e5); no test encodes the M3 invariant (which is how it slipped);
  the 45 type errors in `rebalance.test.ts` mean fixtures no longer satisfy the
  domain types even though they pass at runtime (fold into M2's cleanup).

## Privacy verification

- **No `fetch`/`XMLHttpRequest`/`sendBeacon`/WebSocket anywhere in `src/`.** All
  external URLs are user-initiated link-outs (feedback form, Ko-fi, share intents,
  calendar deep links) with `noopener noreferrer`. `store.ts` touches only
  `localStorage` and file download/upload. The ingest layer is file-based; the Plaid
  adapter is an empty documented stub.
- The **only** violation of the "no network calls" guarantee is the Google Fonts load
  (m1). The commit SHA embedded in the feedback-form URL (`entry.715582229`) is benign
  build metadata, transmitted only when the user opens the form.
- `.gitignore` correctly excludes `/private/`, `*.local.json`, `*.xlsx`; committed
  fixtures under `src/data/` are synthetic.
