## [0.6.0] - 2026-10-23

### Changed

- **Results: accounts with no trades start collapsed** ([#230](https://github.com/rblumen/drift/issues/230)) — on the Results tab, account cards with no trades or transfers now default to the collapsed state so the accounts that need action stay in focus. Click the header to expand; accounts with trades still start open.

### Removed

- **"Revisit placement strategy" warning** ([#232](https://github.com/rblumen/drift/issues/232)) — the Results tab and HTML report no longer warn when taxable accounts hold more of the household than the Fixed Income target. The check ignored your placement rules, so it kept firing after you'd adapted them, and it showed up even on fully balanced portfolios where there was nothing to do. When equities overflow into taxable, the existing placement-spillover note still reports it. Trade recommendations are unchanged.

### Fixed

- **Trades now name the fund to trade when an account also holds a broad fund** ([#228](https://github.com/rblumen/drift/issues/228)) — an account holding a total-market fund (e.g. SCHB) alongside specific cap funds (e.g. VOO, VO) used to get bare rows like "US Mid Cap · SELL" or "US Large Cap · BUY" with no ticker, which read as selling something you don't hold. The trade list now names the specific fund ("VO · SELL"), and buys of the same fund are combined into one row instead of being split between a named and an unnamed line. Rows still go unnamed — for you to pick the fund — when no held fund fits, when two equally specific funds could fill the trade, when the only match is a locked position or a fund you've marked as blended, or when the trade is for a broad class like fixed income (so a taxable account's bond buy isn't silently steered away from munis).

## [0.5.0] - 2026-09-13

### Added

- **Add a position directly within an account, in the Positions tab** ([#222](https://github.com/rblumen/drift/issues/222)) — each account header now carries a quiet "+ Position" control. Clicking it reveals an inline ticker / market value / price entry prefilled to that account, so hand-updating an account with a few positions no longer requires scrolling back to the top-of-page manual-add control. Press Enter to add and keep entering more; Esc or clicking away with an empty ticker collapses it. A position added this way is stamped with the same "just updated" freshness as any other edit ([#212](https://github.com/rblumen/drift/issues/212)). The account header also drops its redundant "N positions" count so the total, % of household, and this control line up with the columns below.
- **Household allocation now shows dollar amounts alongside percentages** ([#216](https://github.com/rblumen/drift/issues/216)) — the Results tab's household allocation table shows each asset class's Current and Target as a percent with the compact dollar amount in parentheses (e.g. "36.0% ($446.4k)"), and Drift now leads with the dollar delta and shows the percent in parentheses (e.g. "+$49.6k (4.0%)"). The After-trades and after-tax columns stay percent-only. The donut/bar/radar chart tooltips and the companion drift table pick up the same compact dollar amounts.
- **Import/update freshness indicator** ([#212](https://github.com/rblumen/drift/issues/212)) — the Positions tab now shows when each account's holdings were last imported or edited (e.g. "Updated just now", "Updated 3 days ago"), so you can tell at a glance which accounts are current and which are stale when prepping a rebalance — and it doubles as confirmation that an import landed. When you update balances by hand one holding at a time, rows you haven't touched yet in the current pass are flagged with a subtle marker so it's easy to see what's left. Freshness is tracked per holding and rolled up to the account; older saves simply read as "not tracked yet" until their next update.

### Changed

- **"Import" tab renamed to "Positions"** ([#221](https://github.com/rblumen/drift/issues/221)) — the workflow tab is now labeled **Positions**, which better reflects that the screen is where you view your holdings, edit balances, add positions by hand, *and* import CSVs — importing being just one way data gets in. The import/CSV wording within the tab is unchanged.

### Fixed

- **Broad funds no longer generate unexecutable single-sleeve trades** ([#215](https://github.com/rblumen/drift/issues/215)) — a held total-market fund (e.g. SWTSX) targeted with a custom cap tilt used to produce a recommendation like "SWTSX · Mid Cap" whose dollar amount could not actually be executed, because buying or selling SWTSX moves large-, mid-, and small-cap together, not one sleeve. The engine now treats any held broad fund (total-market, broad bond, developed-international, alternatives) as a blend of its sleeves: it trades the fund as a unit, labels the recommendation by the fund's true asset class (e.g. "US Total Market"), and adds compensating buy-backs of the sleeves you didn't mean to move so the recommended trades preserve each account's net and land every sleeve on target. The same fix closes an identical latent gap for target-date and other blended funds whose composition is expressed at the parent level. Simple portfolios that target a broad fund at the family level (e.g. a single 30% bond sleeve) are unaffected — no extra trades, no new flags.
- Recommendation and warning reasoning text no longer renders larger than its headline ([#214](https://github.com/rblumen/drift/issues/214)) — expanded flag explanations now use 11px text matching the headline size instead of 14px, improving visual hierarchy.
- **Import source selector no longer renders squeezed** ([#213](https://github.com/rblumen/drift/issues/213)) — the Source card's "Import from file / Class totals / Manual entry" segmented control moved out of the card header, where it competed with the title for width, into its own full-width row in the card body. Segments now render at their natural size on both wide and narrow (mobile) screens, scrolling horizontally instead of squeezing and wrapping their labels when space is tight.

## [0.4.0] - 2026-07-09

### Added

- **Composite buys of blended funds** ([#49](https://github.com/rblumen/drift/issues/49)) — the engine can now *buy* a blended fund (target-date, balanced), resolving the sell/buy asymmetry disclosed in #40/#47: when several asset-class buys in an account line up with the composition of a blended fund the account **already holds**, they collapse into one composite purchase of that fund. Fewer trades to execute, and a deliberately held TDF is no longer slowly depleted by one-way sells. A substitution only happens when it strictly reduces the trade count (at least two per-class buys collapse) and every affected class's projected weight stays within the rebalance target band — no new tolerance knob. Only funds already held with a known decomposition are considered; the engine never assumes knowledge of an account's fund menu. Results and the downloadable report surface each composite with a new informational "Blended fund bought" flag, and a new **Composite buys** toggle on the Strategy tab (default on) disables the behavior.

### Changed

- **"Lock split" icon replaces the "linked" chip on the Strategy tab** ([#43](https://github.com/rblumen/drift/issues/43)) — the toggle that freezes an asset class's sub-class proportions is now an icon-only button (a lock over a pie chart) instead of the ambiguous "linked"/"link" text chip. Lock closed = the split is frozen and a single composite total drives the sub-classes; lock open = each sub-class target is edited independently. The tooltip and accessible label spell out the action ("Unlock split: edit Large Cap / Mid Cap / Small Cap independently"), and the "About the strategy" help text now uses the same lock/unlock language.
- **Spillover flags now explain what fills the preferred bucket** ([#199](https://github.com/rblumen/drift/issues/199)) — a Placement spillover's "See reasoning" expansion (and the downloadable report) now names what occupies the overflowed home instead of a bare "preferred bucket full", e.g. "— preferred bucket full: $10,000 locked (VOO) and $2,000 cash occupy taxable". Occupants cover locked positions (with tickers), fully locked accounts, within-tolerance holdings held in band, and asset classes the placement already routed there — so a spillover no longer reads as contradicting a "Revisit placement" flag when both fire.
- The blended-fund help text on the Classify tab and the "Blended fund sold" flag copy no longer warn about the sell-only asymmetry — with composite buys ([#49](https://github.com/rblumen/drift/issues/49)) both sides now exist.

### Fixed

- Number inputs no longer clip their last digit in current Chrome ([#209](https://github.com/rblumen/drift/issues/209)) — Chrome now shows number-input spinner buttons permanently instead of on hover, which squeezed 4-character values like "57.5" out of the Strategy tab's dense target-% fields. Spinners are hidden app-wide (they were never part of the design); typing, arrow-key, and scroll-wheel stepping are unaffected.

### Added

- **Radar / bar / donut toggle for allocation charts** ([#98](https://github.com/rblumen/drift/issues/98)) — the Household allocation card now offers three lenses on your current-vs-target mix, switchable from a segmented icon toggle: a **radar** (default) with five family spokes (US / Intl / EM / Bonds / Alts, plus Cash when material) where each colored spoke segment is the drift — orange over target, blue under; a **bar** view of vertical bullet bars at the full sub-class level with an orange excess cap, a dashed shortfall box, and a bold target tick; and the familiar **donut**, now recolored to the brand family palette with the "target" marker moved just outside the ring. A companion drift table sits beside the chart, color-keyed to the plot (with per-row family color keys in the donut view) and swapping family rows ↔ sub-class rows with the view. Your chosen view is remembered across reloads. Per-account sections keep their Before/After pie pairs, which pick up the brand palette from #150.

- **Security response headers and a strict Content-Security-Policy** ([#133](https://github.com/rblumen/drift/issues/133)) — `vercel.json` now sends `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and a `Permissions-Policy` denying camera/microphone/geolocation on every response. The CSP restricts scripts, styles, fonts, and connections to the app's own origin (`'self'`), blocks framing and plugin content, and allows no `<form>` submissions — closing off third-party script injection and clickjacking without needing any external hosts, since fonts are self-hosted (#154) and Vercel Web Analytics (#168) beacons same-origin.

- **Anonymous, privacy-preserving web analytics** ([#168](https://github.com/rblumen/drift/issues/168)) — the app now records basic, aggregate site traffic (pageview counts) via Vercel Web Analytics. It is cookieless, sets no cross-site identifiers, and collects no personal or financial data. Your portfolio holdings, account details, and dollar amounts never leave your browser — the analytics only ever sees the page path (always `/`), never your data. Supersedes the auto-generated integration in #167.

- **Meta description and social preview tags** ([#149](https://github.com/rblumen/drift/issues/149)) — `index.html` now has a proper `<meta name="description">` plus Open Graph and Twitter Card tags, so links shared to Slack, iMessage, X, etc. show an accurate title and description instead of nothing.

- Test coverage for the downloadable report and display formatting ([#130](https://github.com/rblumen/drift/issues/130)) — `src/ui/fmt.ts` (currency/percent/share formatting and label/color lookup tables) and the pure HTML-generation logic in `src/ui/exportReport.ts` now have unit tests covering trades, taxable-sale and placement flags, cash/withdrawal sections, locked accounts, and HTML escaping.

- **Blended-fund caption no longer claims blended funds are excluded from trades** ([#194](https://github.com/rblumen/drift/issues/194), relates to [#49](https://github.com/rblumen/drift/issues/49)) — the Classify tab's blended-funds table footer said decomposed funds are "excluded from trade suggestions", but the engine may in fact recommend **selling** a blended fund (disclosed via the BLENDED_FUND_SOLD flag) — it just never recommends buying one. The caption now states the sell/no-buy asymmetry accurately.
- **Household allocation table: help tooltips no longer clipped, and the Drift column's value/bar no longer leaves a dead gap** ([#190](https://github.com/rblumen/drift/issues/190)) — the Drift and After-trades header tooltips were clipped by the table's horizontal-scroll wrapper (added for mobile in #142), since `overflow-x: auto` forces vertical clipping too; tooltips now render in a portal to `document.body`, positioned from the trigger's on-screen location, so they always escape any scroll container — fixed app-wide, not just in this table. Separately, the Drift column's signed value and drift bar were packed to the left of a full-width cell while the column header is right-aligned, leaving a large empty gap at desktop widths and letting bar lengths appear inconsistent; the value and bar are now right-aligned as a group under the header, with the bar occupying a fixed-width track so bar start positions line up consistently down the column.
- **"Target not reachable" banner no longer misfires on portfolios that mix locked positions with on-target classes** ([#117](https://github.com/rblumen/drift/issues/117)) — the post-trade accuracy check compared each class against a target that ignored the locked (immovable) value already sitting in that class. When you held a locked position in one class alongside another class that was left frozen because it was within tolerance, the resulting scale factor could push a perfectly-placed class to spuriously raise the "a hard constraint kept this class off target" flag — or, conversely, mask a genuine miss. The check now measures each class against the resting point the tool can actually reach given its locked holdings, so the flag fires only on real, unreachable drift (e.g. a locked position genuinely stuck above its target).

The warning lists each affected asset class with the selling and buying accounts and points you to your tax advisor. It's conservative: it fires whenever the taxable lot's basis is unknown or shows a loss, and is suppressed only when cost basis confirms the sale is a gain (no loss for the rule to disallow). Each scenario is a self-contained `*.scenario.json` fixture — a realistic portfolio + strategy plus the trades, flags, and projected weights the engine should produce — validated against a Zod schema and run through the engine as its own named test. Fixtures live in principle-numbered subfolders (`01-locked-accounts/`, `05-tolerance-bands/`, `06-tax-placement/`) and show up grouped by principle in the HTML report; adding one requires zero code changes (a glob discovers it). Each `expected` field (`trades`, `flags`, `projectedWeights`, `projectedDriftWithinTolerance`) is optional and asserted only when present, and a wrong expected value prints the scenario description with a readable diff. Ships with three starter fixtures (a no-op, a `REVISIT_PLACEMENT` flag emission, and a locked-account guard) and a `src/engine/scenarios/README.md` for authors. Engine-only; no UI or runtime changes.

- **Expanded asset-class hierarchy — Phase 2a** ([#36](https://github.com/rblumen/drift/issues/36)) — three new allocation dimensions built on the generalized hierarchy below, all opt-in via the portfolio-driven visibility rule (sub-classes stay hidden until held or individually targeted). **Fixed income** is now a parent class that subdivides into `US_TREASURY`, `US_CORP_BOND`, `MUNI_BOND`, `TIPS`, and `INTL_BOND` — the highest-value addition, since each sleeve places by tax treatment (munis in taxable; taxable-coupon bonds shelter in tax-advantaged) instead of one blended bucket. **Developed international** subdivides into `DEVELOPED_EUROPE` and `DEVELOPED_PACIFIC` (≈ MSCI EAFE 62/38). **Real estate** (`REAL_ESTATE`, REITs) is a new standalone top-level sleeve defaulting to tax-advantaged placement. Common ETFs/mutual funds for every new sleeve are mapped (e.g. GOVT/VGIT → Treasury, LQD/VCIT → corporate, MUB/VTEB → muni, SCHP/VTIP → TIPS, BNDX → intl bond, VGK/VPL → Europe/Pacific, VNQ/SCHH → real estate); `MUNY` now maps to `MUNI_BOND`. A user holding a broad bond or developed-international fund against a parent-level target sees no change — holdings roll up and consolidate to the parent, and the sub-classes surface only when explicitly used. Default split weights are anchored on index composition data (Bloomberg US Aggregate, MSCI EAFE) and are fully user-editable.
- **Hierarchy: opt-in subdivision on load** ([#36](https://github.com/rblumen/drift/issues/36)) — parent-level targets for classes legitimately held at the parent level (fixed income, developed international, alternatives) are now preserved on load instead of being auto-split into sub-classes. Only synthetic parents never held at the parent level (US total market → cap sub-classes) still auto-split. This keeps a simple "20% bonds" allocation from silently fanning out into five bond sleeves the user never chose.
- **Generalized asset class hierarchy** ([#36](https://github.com/rblumen/drift/issues/36)) — the engine now supports a declarative parent/child relationship between asset classes. The `CLASS_HIERARCHY` map in `src/engine/hierarchy.ts` is the single source of truth; rollup, resolve, and schema migration all consume it generically. `ALTERNATIVES` is now a parent class with two children: `CRYPTO` (IBIT, FBTC, GBTC, ETHA) and `PRECIOUS_METALS` (GLD, IAU, GLDM, SLV, SGOL). Users who target `ALTERNATIVES` at the parent level continue to get parent-level trade recommendations; users who hold specific sub-class funds see those classes surface automatically via the portfolio-driven visibility rule. A **parent-class consolidation pass** in the engine ensures sub-class holdings count toward the parent target when only the parent is targeted, preventing spurious "sell PRECIOUS_METALS / buy ALTERNATIVES" trades for users who simply hold GLD against an `ALTERNATIVES` target. Greenfield buy recommendations are promoted to the parent level when no sub-class positions exist in the account, so the engine never suggests "buy CRYPTO + buy PRECIOUS_METALS" when the user simply wants ALTERNATIVES exposure. The hierarchy now surfaces consistently across the UI: the Classify dropdown nests sub-classes under their parent; the Strategy **Target allocation** card renders any parent group (not just US Total Market) with indented sub-class rows and the same linked/composite handle — including a **split** control to break a parent target into its sub-classes and a **merge** control to fold them back; the Strategy **Placement rules** card indents sub-classes under their parent and defaults them to the parent's placement preference; and the Results **Household allocation** table indents sub-classes beneath their parent. Sub-class rows stay hidden until they actually carry weight (held or individually targeted), keeping simple portfolios uncluttered.
- **Tax-adjusted allocation** ([#7](https://github.com/rblumen/drift/issues/7)) — opt-in mode that values each account at its after-tax worth before computing drift and target sizes, so a 60/40 target refers to after-tax wealth rather than nominal market value. Roth, HSA, and 529 count at face value; Traditional / 401k balances are haircut by your expected effective rate at retirement (typically lower than your working-age marginal); taxable positions are haircut by the LTCG on their unrealized gain. Cost basis is per-position (auto-imported from Schwab and Fidelity CSVs, manually editable in the Import tab for taxable accounts only). When enabled, the Strategy panel exposes the rate inputs plus a two-row stacked-bar visualization comparing nominal and after-tax composition by asset class, the Results panel adds **After-tax current** and **After-tax projected** columns alongside nominal weights and shows after-tax household value in the header, and the engine drives trade sizing against the after-tax target. A new `MISSING_COST_BASIS` flag fires for any taxable position lacking basis (engine falls back to no haircut, conservatively understating tax drag).
- **Aggressiveness × diversification plot** ([#16](https://github.com/rblumen/drift/issues/16)) — the Household allocation card on the Results tab now includes a 2D scatter plot showing the portfolio's aggressiveness (share in equities & alternatives) against its diversification (normalized inverse Herfindahl across asset classes). A blue arrow from the current point to the projected-after-trades point visualizes the impact of the rebalance, with a dashed green marker for the strategy's target.
- **Next-rebalance reminder** ([#19](https://github.com/rblumen/drift/issues/19)) — set a reminder date for your next rebalance on the Results tab. Pick a preset interval (3 / 6 / 12 months) or any custom date; the Results tab shows an amber/red banner when the reminder is within seven days or overdue. "Mark rebalanced today" stamps the last-rebalanced date and, if an interval was chosen, auto-advances the next due date. "Add to calendar" opens a dropdown with one-click deep links to **Google Calendar, Outlook.com, Office 365, and Yahoo** that pre-fill the event, plus an **Apple Calendar / .ics** download for everything else — all client-side, no calendar API calls.
- **Blended funds are tradeable as a unit** ([#40](https://github.com/rblumen/drift/issues/40)) — target-date funds, balanced funds, and any user-defined decomposed holding are now eligible to be sold whenever the household drift requires it (no longer treated as permanently frozen). The fund's relative composition stays fixed; only the total amount changes. The engine prefers selling non-blended positions first, falling back to a proportional sale of the blended fund only when non-blended capacity can't absorb the needed change. Where proportionality forces over-selling a sub-class, the engine routes a compensating buy via another ticker in the same account so the per-account net stays balanced. A new `BLENDED_FUND_OVERSELL` flag fires when no compensation path exists (e.g. an account whose menu carries no non-blended ticker for the over-sold class), surfacing the residual drift to the user. The position-level `locked` flag remains the escape hatch for "don't touch this specific blended-fund holding." A new informational `BLENDED_FUND_SOLD` flag — surfaced in the Results panel and the exported HTML report — discloses that the engine sold part of a blended fund this run, since there is no symmetric buy-back mechanism and repeated rebalances will trend the allocation away from any blended-fund position the engine has touched.
- **5/25 relative tolerance band** ([#2](https://github.com/rblumen/drift/issues/2)) — `Strategy.toleranceRel` (default 25%) sets a second tolerance band as a fraction of each class's target. The engine now uses whichever band is tighter per class (Bogleheads / Swedroe rule): the absolute band dominates for large sleeves, the relative band dominates for small sleeves. Existing strategies without `toleranceRel` default to 25%.
- **Strategy panel** — new "Relative tolerance" input alongside absolute tolerance, with help-box explanation of the 5/25 rule.
- **"No preference" placement option** ([#21](https://github.com/rblumen/drift/issues/21)) — an asset class can now be set to "No preference" in the placement rules, letting the engine place it wherever account capacity is largest without flagging the result as a spillover. Useful for tax-efficient, broadly-held classes that work in any account type.
- **Retirement drawdown / spending mode** ([#14](https://github.com/rblumen/drift/issues/14)) — raise cash from the portfolio by selling. Total withdrawal = **Σ RMDs** (required minimum distributions, entered manually per account) **+ an additional discretionary amount**. The engine takes RMDs first, then drains withdrawal-eligible accounts in a per-account **drain-priority** order (taxable → traditional → Roth by default, editable), selling down toward the target allocation. Each account gains a three-way **withdrawal eligibility** control — **Restricted / Eligible / Required** (Required reveals an RMD input) — defaulting to Restricted for tax-advantaged accounts (early-withdrawal penalties) and Eligible for taxable. Planned deposits (free cash) and withdrawals run independently in the same pass, netting per account. The Accounts tab shows planned deposits and withdrawals side by side; the Results tab and exported report show a spending-plan table. A new `WITHDRAWAL_SHORTFALL` flag fires when the additional amount can't be fully raised.

The Strategy → Placement-rules dropdowns group these tiers under *Tax-Advantaged*, and a spillover is flagged only when a stated preference genuinely overflows — landing a *Tax-Advantaged*-preferred class in a Roth (which satisfies it) no longer raises a false PLACEMENT_SPILLOVER. New portfolios start with asset-location defaults (US equity / emerging markets / real estate / alternatives → tax-free, taxable-coupon bonds → tax-deferred, munis → taxable). **Existing and imported strategies keep every placement they specified** — the new defaults only fill classes a strategy never set; to adopt them wholesale, use the new **Reset to recommended placement** button.
- **Overview no longer frames placement as a temporary "expiry trigger"** — now that placement preferences are user-configurable per asset class and per account, the Overview tab dropped the "Placement has a built-in expiry trigger" design-assumption blurb, which described the old hard-coded bonds-in-taxable strategy. The `REVISIT_PLACEMENT` flag itself is unchanged — it still fires when taxable assets exceed your Fixed Income target, and remains documented in the Flags reference and Results/Strategy help as a standing heads-up to revisit your placement rules.
- **Rebalances now land closer to your ideal mix** ([#42](https://github.com/rblumen/drift/issues/42)) — previously, once a class drifted past its tolerance band the engine was allowed to correct it back to *anywhere inside* that band, which could leave it sitting right at the edge — so the next small move would re-trigger a rebalance almost immediately. The tolerance band now governs only **whether** a class has drifted enough to act; a new **Rebalance target band** setting (Strategy → Rebalance parameters) governs **how close to ideal** it lands once it does. It defaults to 50% — the engine aims to land within half the tolerance band, leaving drift headroom before the next rebalance. The trade-count-minimization pass respects this tighter band, so it keeps a few more trades than before in exchange for a tighter result; set the band to 100% to restore the prior "land anywhere inside tolerance" behavior (fewer trades, more drift). Existing strategies without the setting default to 50%.
- **Per-account allocation displays match what you hold** ([#78](https://github.com/rblumen/drift/issues/78)) — the per-account **Before / After** pies (in Results and the exported HTML report) no longer break a parent-level holding into sub-classes the data doesn't actually contain. An account whose only holding is a target-date fund decomposed at the parent level (e.g. *US Total Market / Developed Intl / Fixed Income*) previously displayed invented *US Large/Mid/Small Cap* and bond-sector slices, because the pies rendered the engine's internal allocation lens (which redistributes parents into children for drift math, gated on the household *target* granularity). They now render a **holdings lens**: each position is pinned to the class it's classified as, at that holding's natural level, so display granularity matches input granularity. The "After" pie applies each recommended trade at its holding's pinned class — a proportional blended-fund sale stays at the parent level, while a genuinely finer-grained trade (a leaf-fund sell, or a greenfield buy the strategy promotes to a sub-class) shows up at that finer level. The engine's drift detection and trade sizing are unchanged; this is a display-only fix. The household allocation table is unaffected (it legitimately aggregates accounts of mixed granularity).
- **Schwab import now captures free cash on hand** ([#54](https://github.com/rblumen/drift/issues/54)) — Schwab position exports report swept cash on a "Cash & Cash Investments" line whose Symbol column is that label rather than a ticker. The importer was discarding the row (its label contains spaces, like a subtotal line), silently dropping potentially large cash balances from the portfolio. That balance is now imported as a `CASH` position so it counts toward household value and the cash allocation.
- **Spurious "target not reachable" banner** ([#57](https://github.com/rblumen/drift/issues/57)) — a red *Target not reachable* banner could appear with no genuine constraint behind it, from two independent causes. (1) When the only out-of-tolerance class couldn't be rebalanced because the classes it would trade against were all within tolerance and therefore frozen by the 5/25 rule — expected behavior, not a hard constraint. The post-trade accuracy check now compares each class against its *reachable* target (scaled for the frozen capacity) instead of the nominal target. (2) For a class targeted at **0%** (e.g. Cash), the relative tolerance band collapses to `0.25 × 0 = 0`, so any residual the engine couldn't trade away — a sub-`minTradeUsd` sweep, a locked sliver, or floating-point dust — tripped the flag even though the class had been swept toward zero correctly. The accuracy check now also ignores any deviation smaller than your **minimum trade size** (`minTradeUsd`): a gap that would take a trade you've already opted out of isn't actionable, so it's no longer flagged. Genuine constraints (a locked position above target, no eligible account, or a material deviation fragmented below the trade threshold across accounts) still surface.
- **Selling a cash position is not a taxable trade** ([#56](https://github.com/rblumen/drift/issues/56)) — reducing a money-market or cash holding (e.g. SPAXX) to fund purchases no longer triggers a `TAXABLE_SALE` warning, since depleting cash carries no capital-gains exposure. In the "How this rebalance is funded" breakdown, freed cash now appears in the left box alongside new contributions (label updated to "Funded by new & free cash") and is excluded from the "Requires sales" total on the right. The per-trade **⚠ taxable sale** badge in the trades table and exported HTML report is now suppressed for cash positions too — previously the engine flag was suppressed but the row-level badge still appeared, because the table and report each re-derived "is this a taxable sale" independently. All three now read one shared engine predicate, so they can't drift apart again.
- **Aggressiveness stable across split/merge** ([#61](https://github.com/rblumen/drift/issues/61)) — toggling a parent class between split and merged no longer causes a jump in the "X% growth · Y% defensive" gauge or the AllocationPlot aggressiveness axis. Both now derive the defensive set from the hierarchy (`FIXED_INCOME` + all sub-classes + `CASH`), so whether bonds are held at the parent level or split into Treasury/Muni/TIPS/etc., and whether Developed Intl is split into Europe/Pacific sub-regions, the reading is the same.
- **Strategy: "merge" reappears after split** ([#59](https://github.com/rblumen/drift/issues/59)) — clicking **split** on a parent class (Alternatives, Fixed Income, Developed Intl) distributed its weight into sub-class targets but then permanently hid the **merge** link, leaving no way to undo the split. The merge button is now suppressed only when a child class is *held* in the portfolio (you can't hide real positions); a split that only set targets with no current holdings is always reversible.
- **Small absolute drift below the minimum trade size is now tolerated** ([#57](https://github.com/rblumen/drift/issues/57)) — the post-trade accuracy check no longer raises *Target not reachable* for a class whose remaining drift is smaller than `minTradeUsd`. Previously a needed adjustment suppressed by the minimum-trade filter would still flag; now, since you've chosen not to make trades that small, the leftover drift is treated as acceptable rather than an error.
- **Strategy panel** — the Target allocation and Placement rules cards are now collapsible; click the section heading to show or hide the card.
- **Per-account deposit limits** ([#30](https://github.com/rblumen/drift/issues/30)) — account deposit eligibility is now a three-way choice: **Open** (any share of household free cash), **Limited** (capped at a dollar amount), or **Closed** (none). Use "Limited" when a contribution limit is partly consumed — e.g. a Roth IRA with room left this year. Each account is clamped at its limit, and overflow spills to accounts with remaining room; anything that still can't be placed surfaces as `EXCESS_CASH`. An account's own new cash always deploys in full regardless of the limit. The Accounts table, Add/Edit forms, Results cash-deployment table, and exported HTML report all show the new state.
- **Demo sample portfolio rescaled to ~$100k** — the bundled synthetic fixture (loaded via `?demo` or the Import tab) now totals ~$100k of net worth instead of ~$1M, sized to feel familiar to a typical early- or mid-career saver. The five accounts, drift scenario, and every demonstrated feature (locked positions, account restrictions, concentrate rules, ticker override, blended fund, new cash, household free cash, deposit-closed account) are preserved at the smaller scale. `minTradeUsd` lowered from $250 to $100 to match the new portfolio size.
- **Free-cash routing now concentrates instead of spreading** ([#37](https://github.com/rblumen/drift/issues/37)) — household free cash is deployed into the single largest-capacity eligible account first, spilling to additional accounts only when a deposit limit forces it. Previously it was split across all eligible accounts in proportion to their value, which touched more accounts and generated more trades without improving the allocation. This minimizes the number of accounts traded (in line with the tool's trade-minimization goals).

### Fixed

- **Free cash now appears in the account breakdown** ([#83](https://github.com/rblumen/drift/issues/83)) — uninvested cash (a per-account contribution, plus each account's share of distributed household free cash) counts toward household value but was missing from every per-class breakdown — only a cash-classified *holding* like a money-market position showed up. As a result the per-account **Before** pie summed to less than the account's value, and the cash the engine deploys appeared in **After trades** with no visible source, so trades looked unbalanced (the account seemed to grow out of nowhere). An account's **in-account idle cash** now shows under **Cash** in its Before pie, and the household allocation table reflects all cash on hand (idle + free cash to deploy), so Before and After totals reconcile and the current column sums to 100%. The deployed portion is consumed from Cash in the After view; any free cash left undeployed (e.g. when everything is within tolerance) stays visible as Cash. Trade calculations are unchanged — this is a display fix. (Household free cash routed *into* an account is shown as a deposit transfer rather than pre-existing cash — see #84/#87.)
- **Per-account "Net" now reflects money moving in or out, not internal reshuffling** ([#87](https://github.com/rblumen/drift/issues/87)) — an account's **Net** change previously summed its trade dollars, so deploying cash that already sits in the account (now shown in its Before breakdown, per #83) read as a positive inflow even though the balance didn't change — you were only converting cash to securities. Net is now the account's **net external transfer**: household-free-cash **deposits** in, **withdrawals** out. Deploying in-account idle cash nets to **$0**; a deposit shows **+$X**; a withdrawal shows **−$X**. Trade math is unchanged.
- **Trade list granularity matches pie chart** ([#36](https://github.com/rblumen/drift/issues/36)) — when the strategy targets child asset classes individually (e.g. `CRYPTO: 1.5%, PRECIOUS_METALS: 1%`), the trade card now shows separate child-level buy recommendations instead of a single collapsed parent-level "Alternatives" trade. The greenfield-buy promotion that collapses all-sibling unresolved buys to the parent is now gated on whether the strategy is operating at parent granularity; child-level targets suppress promotion so the trade list stays in sync with the projected-weights pie chart.
- **Sub-class placement** ([#36](https://github.com/rblumen/drift/issues/36)) — the placement engine iterated a hardcoded class list for ordering and silently skipped any asset class not enumerated there, so a directly-targeted hierarchy sub-class (e.g. `CRYPTO`, `MUNI_BOND`) could be left unplaced with no trades generated. Placement now orders every asset class, using the hardcoded list only to break ties.
- **Robustness to partial strategies** ([#36](https://github.com/rblumen/drift/issues/36)) — `rebalance` now normalizes its target map so a strategy object missing a class key treats it as 0% rather than producing `NaN` drift, which previously zeroed out every trade. Schema-parsed strategies were already complete; this hardens direct engine callers.

## [0.1.0] - 2026-05-29

### Added

- **Rebalancing engine** (`src/engine/`) — pure TypeScript, fully unit-tested household-level rebalancer covering target-weight drift detection, greedy asset-class placement across account tiers (taxable / tax-advantaged / education), new-cash deployment to underweight classes, and absolute tolerance / minimum-trade filtering.
- **Ingest layer** (`src/ingest/`) — CSV adapters for Empower, Schwab, and Fidelity brokerage exports normalised into a single `Position` schema; manual entry fallback; institution-aware field parsing.
- **Five-panel UI** — Import, Classify, Strategy, Results, and Overview tabs wired end-to-end to the engine.
- **Strategy panel** — editable target weights with linked US cap-class sub-allocation, per-asset-class placement rules, tolerance band and minimum-trade controls, and new-cash input.
- **Results panel** — household allocation before/after side-by-side pie charts, per-account trade cards, engine flag annotations (`TAXABLE_SALE`, `REVISIT_PLACEMENT`, `UNMAPPED_HOLDING`, `PROJECTED_OFF_TARGET`, `WASH_SALE_RISK`, etc.), and a downloadable HTML report.
- **Placement ordering** — placement tier preference derived dynamically from strategy constraints rather than a fixed hierarchy; greedy fill concentrates trades into the fewest accounts and drops marginal trades that fall within tolerance.
- **Persistence** — auto-save to localStorage on every change; JSON export/import for manual backup; full portfolio reset.
- **Demo mode** — `?demo` URL parameter loads a synthetic sample portfolio for exploration without real data.
- **Engine flag: `PROJECTED_OFF_TARGET`** — warns when post-rebalance weights are projected to remain outside tolerance, with a stress-test suite.
- **GitHub Actions CI** — Vitest runs on every push and pull request.
- **Vercel deployment** — preview and production deploy configuration.

### Architecture

- Engine is framework-free; UI and ingest depend on the engine, never the reverse.
- All computation is client-side — no backend, no network calls, no telemetry.
- Synthetic fixtures only; real financial data is git-ignored.
